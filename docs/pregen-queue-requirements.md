# 需求定稿：后台预生成队列（Pre-generation Queue）

> 状态：已定稿（2026-10-06）。实现前如需变更，直接修改本文并在「决策记录」中补一行。

## 1. 目标

把现有的「单篇前台预生成」（`Player.pregenerateAll`）升级为**持续运行的后台批量生成**：多篇笔记排队，逐篇逐句合成落缓存；提供独立页面查看队列与进度，可随时启停。生成的音频进入现有 IndexedDB 句子缓存，播放侧零改动即可无缝受益（已缓存句子播放时不再请求）。

## 2. 核心模型

- **任务（Task）= 笔记 + 账号 + 音色**，三元组即任务唯一标识（与缓存 key 的维度对齐）。
  - 同一笔记、不同账号或不同音色 → 各自独立的队列项，互不干扰，缓存互不覆盖。
  - 入队时**快照音色**：取入队那一刻 `resolveActive()` 得到的 `accountId + voice`（含面板 `voiceByAccount` 覆盖值）。
  - 任务执行时读账号的**当前**配置（baseUrl/model/语言等），配置修改立即生效；缓存 key 随之变化，进度自动重算，与播放侧行为一致。
- **任务进度 = 已缓存句子数 / 该笔记总句子数**（`buildUnits` 断句后逐句查缓存命中；断句与播放/正文标注共用同一套逻辑）。
- **队列 = 有序任务列表**，持久化，重启 Obsidian 后恢复并自动继续。

## 3. 功能需求

### 3.1 入队（纯手动）

- 入口：
  - 文件浏览器右键菜单（文件/文件夹）「加入预生成队列」；文件夹递归收集 md 笔记；
  - 命令面板「将当前笔记加入预生成队列」；
  - 播放面板现有「预生成」按钮 → 改为把当前笔记入队并**立即开始执行**（保持一键预生成体验，但走队列）；
  - 设置页「按笔记缓存管理」处增加「重新生成」入口。
- **去重**：同一 笔记+账号+音色 已在队列中（含等待/生成中）→ 不重复入队，提示并可置顶。
- 已完成的同一任务再次入队 = **增量刷新**：重新断句，只合成新增/改动句，无缺口则瞬间完成并提示「0 句需生成」。
- 系统语音（Web Speech，`capabilities.pregeneratable === false`）入队时拦截并提示。

### 3.2 队列页面（独立 ItemView）

新增独立视图「预生成队列」（ribbon/命令打开），不塞进播放面板。

- **顶部全局区**：总开关（启动/暂停）、总进度（全部任务 done/total 与百分比）、当前正在生成的笔记名、失败句计数。
- **任务行**：笔记标题 · 配置（账号 · 音色）· 进度条 + `done/total` · 状态（等待中 / 生成中 / 已完成 / 部分失败 x 句 / 已取消 / 已过期）。
- **行操作**：取消、重试（仅重试失败句）、置顶/上移/下移、点击打开笔记。
- 完成时 Notice 通知（可关）。

### 3.3 执行控制与并发模型

- **全局启停**：暂停 = 保留队列可恢复（默认操作）；停止 = 清空未完成任务（二次确认）。
- **并发**（调度粒度为**句子级**，队列按序取任务，有空闲槽位就填句子请求）：
  - 每个账号设置**最大并发**（默认 1）：该账号下跨所有队列任务（不论音色、笔记）的在途合成请求数上限；
  - 每个账号可标记**「本地 TTS」**（默认否）：所有本地 TTS 账号的在途请求**总数**另受全局设置「本地 TTS 总并发」约束（默认 1）——瓶颈是本机算力，所以要跨账号总控；
  - 云端账号之间不设跨账号上限（不同服务、不同 key，互不争抢）；
  - 不设全局请求间隔（由每账号并发 + 429 退避覆盖）。
- **顺序**：FIFO，手动置顶/上移/下移可调。

### 3.4 播放与队列的协调（「让路」而非「暂停」）

默认策略为让路：

- 播放触发的即时合成（当前句未命中缓存时的合成、以及预取下一句）拥有**最高优先级**：立即可发，不进队列的并发槽排队；账号槽位被占满的极端情况下允许临时超出上限 1–2 个在途请求，**播放永不等待**。
- 队列正在途的请求不中断、照常完成；队列调度照常继续。
- **播放命中缓存（句子已生成）时不产生任何合成请求，队列零感知、全速运行。**
- 同一句子同时被播放与队列请求 → 共享 in-flight 去重，只发一次。
- 设置项「播放时的队列行为」：**让路（默认）** / 暂停（播放期间挂起整个队列，保守选项）。

### 3.5 失败与重试

- 单句失败：自动重试 2 次（指数退避；429 额外加长），仍失败则记录并**继续后续句子**，不中断整篇。
- 任务级：有失败句的任务标「部分失败（x 句）」，可一键重试失败句。
- **连续 10 句失败**（典型场景：账号失效、端点挂了）→ 队列自动暂停 + 通知，避免空转。阈值写死，不做设置项。

### 3.6 与笔记生命周期的联动

- 笔记编辑：任务**每次开始执行时重新断句**（不用入队时的快照），新句子合成、旧句子缓存自然命中——增量生成，改一段不用重合成整篇。
- 笔记改名/删除：沿用现有 `storage.renameNote/removeNote`，队列任务同步改路径/移除并标「已过期」。
- 账号删除 → 其任务标「已过期」，可一键清除。
- 设置页手动清理某笔记缓存后，任务进度如实回落（进度每次执行前重算）。

### 3.7 持久化

- 队列（任务列表 + 顺序 + 每任务失败句记录）持久化（插件数据或 IndexedDB 独立 store）。
- 重启 Obsidian 后恢复队列并**自动继续执行**。

### 3.8 设置项汇总

| 设置 | 位置 | 默认 |
| --- | --- | --- |
| 账号最大并发 | 账号编辑弹窗 | 1 |
| 是否本地 TTS | 账号编辑弹窗 | 否 |
| 本地 TTS 总并发 | 全局设置 | 1 |
| 播放时的队列行为（让路/暂停） | 全局设置 | 让路 |
| 重启后自动继续队列 | 全局设置 | 开 |
| 完成通知 | 全局设置 | 开 |

## 4. 非功能需求与约束

- 后台执行全异步、事件驱动更新 UI，不阻塞主线程；队列页关闭时队列照常运行。
- 移动端可用；系统切后台/熄屏时队列自动暂停，回前台续跑（不承诺后台持续生成）。
- 存储观测：队列页展示本批已生成字节数；IndexedDB 配额不足时给出明确错误与清理引导（衔接设置页缓存管理）。
- 现有 `Player.pregenerateAll` 的已知问题（遍历 `this.units` 活引用、切笔记不取消，中途切换会「串台」）随本需求一并消除——该方法被队列 worker 取代。

## 5. 实现方向（非需求本身）

- 把 `Player` 内的 `synthesizeAndStore` 抽成共享合成服务（含 in-flight 去重），播放预取与队列 worker 共用；播放请求走优先通道（见 3.4）。
- 新增 `src/core/pregen-queue.ts`（队列状态机 + 持久化 + 并发调度）与 `src/ui/queue-view.ts`。
- `AudioStorage` 增加按 key 批量存在性查询，用于快速计算任务进度。
- 账号模型（`TtsAccountConfig`）增加 `maxConcurrency`、`isLocalTts` 字段（旧数据缺省 = 1 / false）。

| 1 | 任务身份 | 笔记 + 账号 + 音色；入队快照音色；执行时读账号当前配置；账号删除 → 任务过期 |

| 5 | 播放协调 | 让路优先：播放合成永不等待、可临时超发 1–2 请求；命中缓存则队列零影响；设置可选「暂停」模式 |

| 7 | 请求间隔 | 移除（并发 + 退避覆盖） |
| 8 | 完成任务去留 | 保留为历史，「清空已完成」按钮；再次入队 = 增量刷新 |
